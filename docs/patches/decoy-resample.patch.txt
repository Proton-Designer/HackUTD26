PROBLEM: to_pcmu_frames() downsamples Magpie's 22.05 kHz to 8 kHz with a 3-tap moving average + np.interp (linear). That barely filters: everything above 4 kHz
folds back into the speech band (4.5k -> 3.5k at -6.9 dB, 5k -> 3k at -8.8 dB, 6k -> 2k at -14.5 dB). TTS fricatives (s, sh, t, f) and breath live at 4-10 kHz, so
the phone line gets metallic/buzzy noise: the "robotic" sound.

FIX: numpy-only polyphase resampler (scipy is NOT in decoy/.venv): Kaiser(beta 5.65, 96 taps, ~60 dB stop-band) windowed-sinc low-pass, 3.6 kHz corner, evaluated at the exact
fractional input position of every output sample (22050 -> 8000 = 320/882, 320 phases, table cached, each phase normalised to unity DC gain). Then peak-normalise the
utterance to ~ -3 dBFS (23000/32768; gain capped at 4x = +12 dB; near-silence with peak <= 200 is left alone; np.rint + clip so it never clips), same mu-law table, same
160-byte frames, same silence padding. Signature and return type unchanged (bytes in, list[bytes] out), so decoy/app.py, core.py, tests need no change.
