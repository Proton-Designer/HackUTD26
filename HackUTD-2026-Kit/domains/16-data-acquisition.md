# Data acquisition and evidence quality

## Use this when
- Hour 0-3: the chosen idea depends on data and the team must pick a source, an owner, and a deadline for having data in hand.
- A source fails mid-build: an API returns one page, a portal caps downloads, a page comes back as an empty JS shell, or a site starts returning 403/429.
- Someone says "let's just scrape it" or "let's have the LLM generate 500 examples."
- A dataset has just loaded for the first time and nobody has profiled it yet.
- Hour 14-20: a statistic, accuracy figure, or chart is about to go on a slide or the Devpost page.
- Q&A prep: answers to "where's the data from?", "is it real?", "how do you know it's accurate?", "is scraping this legal?", "what about privacy?"

## Core principles
1. **Demo from a local snapshot; the live pull is an optional extra.** Sites go down, change layout, rate-limit, and expire keys mid-event, and a full snapshot is simpler than incremental pulls at hackathon scale. Save raw responses with timestamp and source URL on the first pull, then test the app with wifi off. [Web Scraping with Python, p.80]; [Fundamentals of Data Engineering, p.355-356, p.384]; [Seed: 0. Synthesis / Playbook, §3]
2. **Walk the acquisition ladder top-down, and only use data you can open in the next 30 minutes.** Order: sponsor data, official API, open portal or bulk download, curated repository with provenance traced to the original, polite scraping, own collection at the event, labeled synthetic. Records requests take two weeks to four months and sometimes end in rejection, so they are a "next step," never a plan. [Seed: 0. Synthesis / Playbook, §2]; [Data Journalism Handbook, p.43]; [Seed: A. Hackathon Kit, §A3]
3. **Before writing an HTML parser, look for the hidden JSON endpoint.** Open the browser Network tab before loading the page and filter by XHR or by your search term. Mitchell's Target example takes about 260 requests and megabytes through Selenium versus 1 request and about 10 KB through the API. Order: plain request, JSON inside `<script>` tags, hidden API, then headless browser last. [Web Scraping with Python, p.315-318, p.306]
4. **Prove the data can answer the question before you build on it.** Load it and plot the key variables within 20-30 minutes. If the signal the idea needs is not visible by hour 6, switch data or idea. Name the question type (descriptive, exploratory, inferential, predictive, causal), because the type caps what you can honestly claim. Most 24h projects should not claim causal. [Elements of Data Analytic Style, p.8-12, p.92]
5. **Read everything as text first, then convert deliberately and count what failed.** CSV stores no types, so ZIP and FIPS codes lose leading zeros, ambiguous dates swap day and month, and sentinels (0, -1, 999, 99999, 1970-01-01) load as real values that skew averages. Use `errors="coerce"` and report the NaN count. A jump in missing dates means a format you did not expect. Exactly 65,536 or 1,048,576 rows means spreadsheet truncation. [Python for Data Analysis, p.275, p.279-280, p.322-323]; [Elements of Data Analytic Style, p.24-25]; [Seed: B. The Quartz Guide to Bad Data, §Your source should fix]
6. **Hand-verify 20 random rows against a second source and report the match rate.** (counterintuitive) Aggregated and third-party data is error-prone: even regulated credit reports had a serious error affecting about 5 percent of consumers. The Guardian's verification against police records found cases its team had missed. A stated error rate earns more trust from judges than claiming the data is clean. [Weapons of Math Destruction, p.133-135]; [Data Journalism Handbook, p.48-49]
7. **A small direct dataset beats a large proxy dataset.** (counterintuitive) Proxies like zip code, name, or credit score answer "how have people like you behaved?" and bring group membership in with them. Florida drivers with clean records but poor credit paid about $1,552 a year more than drunk drivers with excellent credit. For each column, write down what it actually measures. [Weapons of Math Destruction, p.145, p.129-130]
8. **If no dataset exists, build one by hand and pitch it as the differentiator.** (counterintuitive) Below about 200 records, splitting rows among teammates in a shared sheet beats writing a scraper. Lock column names, units, date format, and allowed values before anyone starts. A compiled dataset is something competitors cannot easily copy. [Data Journalism Handbook, p.45-49, p.47-48]
9. **Insight usually comes from one join of two sources on a shared key.** Overlaying palm plantations on protected areas found 7,000 illegally planted hectares. Re-serving a single API mostly republishes someone else's database. Pick one key (location, company, date) and produce one overlap number. [Data Journalism Handbook, p.26-27]; [Web Scraping with Python, p.318-322]
10. **Every join can silently drop or multiply rows.** Inner joins quietly drop unmatched keys, and many-to-many keys form a Cartesian product (3 x 2 matching rows give 6). Pass `on` and `how` explicitly, print row counts before and after, and use `indicator=True`. Unmatched keys usually reveal a key-format mismatch. [Python for Data Analysis, p.361-366]
11. **Synthetic data is for seeding and stress tests, never evidence.** LLM-generated test sets are more predictable than real input, so they inflate scores, and repeated generation narrows diversity. They fail on specialized documents, dialects, high-stakes domains, and underrepresented groups. Label it in the UI and README. [Seed: G. Synthetic Data, §Tian Pan, §Husain]; [Seed: A. Hackathon Kit, §A9]
12. **"Public" is not permission; stop at the first block.** Run a three-part triage: facts or creative content? behind access control? would your volume cost the owner money? hiQ v. LinkedIn is often misread: hiQ still lost on breach of the user agreement. In the eBay case, ignoring a cease-and-desist and rotating proxies at about 100,000 hits/day led to a lawsuit. Show aggregates, not republished text. [Web Scraping with Python, p.38-41, p.50-52]; [Seed: E. Web Scraping: Law and Ethics, §hiQ Labs v. LinkedIn]

## Decision procedure
Main decision: which source do we commit to, and is the data good enough to build the demo and its claims on? The data owner runs this; everyone else builds against a 100-row sample or a mock until step 6 passes. [Python for Data Analysis, p.308]

1. **Data-need worksheet (10 min, at kickoff).** Write the question the demo must answer, one row = ?, fields needed, geography and time range, minimum rows for the demo to feel real, freshness needed, and 3 ranked candidate sources plus a fallback. Sketch the final 5-10 column table on paper, including a date and a location column. [Seed: A. Hackathon Kit, §A1]; [Data Journalism Handbook, p.46-48]
2. **Find before you fetch (20-30 min, hour 1).** Ask the sponsor table what data and APIs they provide; sponsor data often decides track fit. Then check the official portal for the domain (Dallas OpenData and the Texas Open Data Portal via Socrata, Census API, FRED, NOAA, CDC/CMS, World Bank). If 15 minutes of searching finds nothing, switch to building your own or to a proxy, and write down what that proxy misses. [Seed: A. Hackathon Kit, §A2]; [Data Journalism Handbook, p.27, p.39]
3. **2-minute triage per source. Reject a source that fails any of these:** access works right now (key issued, no approval wait); downloadable and loadable in under 30 minutes; license allows your use; field meanings documented. For a Kaggle or Hugging Face upload, trace and cite the original publisher. [Seed: A. Hackathon Kit, §A3]
4. **Scrape only if steps 2-3 failed.** First look for a print view, mobile site, or another site publishing the same data. Check robots.txt and terms (2 min). Plan for one targeted, one-time snapshot at about 1 request per 1-2 seconds, single-threaded, with a User-Agent that names your project and a contact. A single table can be copied and pasted instead. Time-box each source to about 45 minutes; when the box expires, switch sources. [Web Scraping with Python, p.43-44, p.57-58, p.111-112, p.181]; [Seed: A. Hackathon Kit, §A5]
5. **Sample end to end (by end of hour 1).** Load 100 rows into the real storage and render one result in the UI. Write down the 5-10 fields you actually use, with types and quirks, from real responses, not from the docs alone. Confirm pagination: a bare GET usually returns one page (McKinney's GitHub example returns 30 issues). [Fundamentals of Data Engineering, p.350-351, p.358]; [Python for Data Analysis, p.303-304]
6. **Go/no-go gate (by hour 6).** Go only if: the profiling script runs clean, the needed signal is visible in a plot, row loss from cleaning is explained, and the 20-row spot-check match rate is acceptable to state aloud. If the signal is missing: change the data or the claim, not the chart. If a source is capped or refused: within 15 minutes try a partner organization, mirror, or cached copy, then fall back to a smaller sample (Bogota's Botanical Garden capped downloads at 10,000 of 1.2 million rows; a collaborating organization handed over the full set). [Elements of Data Analytic Style, p.8]; [Data Journalism Handbook, p.33]
7. **Freeze (before the final rehearsal).** Snapshot committed, `make_data.py` rerun on a teammate's clean machine with identical output, "last updated" timestamp and record count visible in the UI, data card in the README. [Elements of Data Analytic Style, p.96]; [Fundamentals of Data Engineering, p.383-384]

## Checklists

**First-load audit (run on every new dataset, 15-45 min)**
- [ ] Printed the raw head of the file: header row, junk or comment rows, delimiter, encoding, thousands separators. [Python for Data Analysis, p.275-280]
- [ ] Shape, dtypes, nulls per column, and exact duplicates printed. Top-5 value counts checked in every column for 0, -1, 999, "N/A", "other", "refused". [Seed: A. Hackathon Kit, §A6]
- [ ] Missingness examined before dropping: does it cluster by group, region, or time? Use `dropna(how='all')` or `thresh=`, not the default drop-any, and print row counts before and after. [Python for Data Analysis, p.309, p.311-313]; [Elements of Data Analytic Style, p.37-38]
- [ ] Units and scale plausible (180-inch people means centimeters), and labels consolidated through an explicit mapping table after lowercasing and stripping whitespace. [Elements of Data Analytic Style, p.25-26]; [Python for Data Analysis, p.320-321]
- [ ] Uniqueness key defined. Same ID with different values gets investigated, not silently deleted. [Seed: A. Hackathon Kit, §A7]
- [ ] Totals reconciled against one published aggregate. [Seed: B. The Quartz Guide to Bad Data, §Your source should fix]
- [ ] Assertions in the script (no nulls in keys, value ranges, row count in expected range), with rejects written to a `bad_rows` file and the reject rate reported. [Fundamentals of Data Engineering, p.361]

**Before any number goes on a slide**
- [ ] The definition and denominator are written beside it. Who is counted, and what happened to non-responders? (Law schools counted non-responding alumni as employed.) [Weapons of Math Destruction, p.64]
- [ ] Re-cut by 2-3 obvious subgroups to check for Simpson's paradox. (SAT averages fell nationally while rising within every income group.) [Weapons of Math Destruction, p.122]
- [ ] The finding still appears in the 30% held out before exploring; if it vanishes, drop it. The number of things tried is counted, and if more than a few, the finding is framed as "worth following up." [Elements of Data Analytic Style, p.41, p.44-45]
- [ ] Wording is "associated with," not "causes." An uncertainty range and n are shown. Rows and independent units (users, days, sources) are reported separately. [Elements of Data Analytic Style, p.12-13, p.45-46, p.48]
- [ ] Margin of error is under about 10% of the value, or the number is framed as an estimate. Money is inflation-adjusted, and a seasonal series is seasonally adjusted. [Seed: B. The Quartz Guide to Bad Data, §You should fix]

**Data card and judge line (README, 10 lines)**
- [ ] Source and URL, license, pull date and method, one row = ?, row count, time range, geography, cleaning steps (link to script), known gaps and biases, real vs seeded vs synthetic, personal data handling. [Seed: A. Hackathon Kit, §A10]; [Elements of Data Analytic Style, p.18-19]
- [ ] Selection method stated: all records, first N, filtered, or random. [Elements of Data Analytic Style, p.18-19]
- [ ] One rehearsed sentence: "Our data is X from Y, pulled Saturday, covering Z; its main limitation is W." [Seed: 0. Synthesis / Playbook, §10]

## Anti-patterns
- **Live API in the judging loop.** Tell: the demo breaks on venue wifi or a 429. Fix: read from the committed snapshot and keep the live call behind a toggle. [Fundamentals of Data Engineering, p.384]
- **Selenium by default.** Tell: a laptop fan spinning to scrape a site whose data arrives as JSON. Fix: spend 10 minutes in the Network tab first. [Web Scraping with Python, p.315]
- **Positional selectors.** Tell: `find_all('table')[4]` in the code, and odd rows appear on page 2. Fix: anchor on id, class, text, or a nearby landmark. [Web Scraping with Python, p.95, p.110-111]
- **Editing raw files or cleaning in spreadsheet cells.** Tell: nobody can reproduce the clean table, and "raw" has been touched. Fix: keep `data/raw/` read-only and have one script produce `data/clean/`. Notes go in a `flag` column, never in cell color. [Elements of Data Analytic Style, p.15-20, p.24]
- **Synthetic data presented as proof.** Tell: "92% accuracy" measured on LLM-written test cases, or "users want this" based on generated personas. Fix: report the metric on real examples, even 20, and label the synthetic data. [Seed: G. Synthetic Data, §Tian Pan]
- **Invented composite score.** Tell: a dashboard "score" with weights chosen by gut. Fix: show the weights, or ship sliders and filters over the raw columns. [Weapons of Math Destruction, p.51, p.64-65]
- **Missing treated as negative.** Tell: users with no history get a low score. Fix: build an explicit "insufficient data" path. Never score individuals from a few dozen points. [Weapons of Math Destruction, p.14, p.109, p.123]
- **Faked granularity.** Tell: monthly numbers that are an annual total divided by 12. Fix: show the true grain or find finer data. [Seed: B. The Quartz Guide to Bad Data, §Your source should fix]
- **Escalating against a block.** Tell: rotating proxies or user agents after 403s. Fix: stop and switch to another site, a cache, or sponsor data. [Web Scraping with Python, p.50-52]
- **Collecting PII "just in case."** Tell: emails or names in the demo database that no feature uses. Fix: do not collect them; data never collected cannot leak. Naive hashes of emails are reversible. [Fundamentals of Data Engineering, p.381-383]

## Hackathon calibration
- **Budget data work as the critical path.** Loading and cleaning commonly takes 80% or more of analysis time. Assign one data owner with a cleaned-table checkpoint around hour 6, and have everyone else build against a small sample or mock until then. [Python for Data Analysis, p.308]
- **Ignore most data-engineering infrastructure.** Skip streaming, Kafka, incremental CDC pulls, dead-letter queues (a `bad_rows.csv` is enough), resumable crawlers (just rerun a short crawl), and warehouse batching (row inserts into SQLite or Postgres are fine at this scale). Monitoring becomes a visible "last updated" timestamp and record count. [Fundamentals of Data Engineering, p.357, p.361, p.383-384]; [Web Scraping with Python, p.199-200]
- **Keep "near real-time" honest.** Poll every 30-60 seconds or refresh on click. Time the event-to-screen delay once and quote that number instead of saying "real-time." [Fundamentals of Data Engineering, p.342-345, p.344]
- **Webhooks:** use a serverless function that writes the raw payload and returns 200, and keep a replayable sample payload so the demo does not depend on the provider firing. [Fundamentals of Data Engineering, p.374-375]
- **Shrink the paperwork.** The seven-section datasheet becomes the 10-line data card. Formal multiple-testing correction becomes "count what you tried and say it." [Seed: D. Datasheets for Datasets, §Hackathon reading]; [Elements of Data Analytic Style, p.44-45]
- **Crawl budget is generous if started early.** At 2 seconds per page, one laptop fetches about 14,000 pages in 8 hours. Start by hour 4 in the background and develop against the partial result. [Web Scraping with Python, p.43-44]
- **Judges reward data work.** In a 4-minute slot, a stated method ("hand-checked 20 rows, 19 matched"), a visible source credit on the main screen, and one "what this data misses" line read as rigor, not weakness. A records request is a next step, not something to apologize for. [Data Journalism Handbook, p.40, p.43]; [Elements of Data Analytic Style, p.42, p.47]
- **Collect your own evidence at the venue.** A waitlist page, instrumented events, and hallway task logs are real data. Report "N people signed up during the event," not projections. [Seed: A. Hackathon Kit, §A8]

## Where experts disagree
- **Hand entry vs scraper vs automation.** The Data Journalism Handbook says to use the simplest method and hand-enter under about 200 rows (p.47). Mitchell treats scraping as a legitimate MVP bootstrap (p.62-63). Reis warns that manual exports get lost (p.375, opinion). Follow: a one-time manual download or hand entry is fine if date-stamped and committed; scrape only for hundreds of uniform records; Reis's concern applies to ongoing pipelines, not a 24h snapshot.
- **Fill or leave missing.** McKinney shows `fillna` with mean, median, or capped forward-fill (p.314-316). The seed cleaning rules and Leek say to leave values missing and flag imputation (A7; p.23), and O'Neil warns that missing must mean unknown, not negative (p.109). Follow: never fill values behind an evidence claim; fill only for display or model input, with an `imputed` flag column and the method disclosed.
- **CSV vs typed formats.** Reis says CSV is error-prone and recommends Parquet, Avro, or JSON (p.372-373). McKinney and Leek prefer CSV for interchange and plain-text sharing (p.296-300; p.18). Follow: commit a CSV that teammates and judges can open, load it with explicit dtypes, and add a binary cache only if load time hurts. Pin library versions if you pickle.
- **robots.txt weight.** Mitchell calls it a courtesy signal with no enforcement (p.46-49). The seed notes courts treat compliance as evidence of good or bad faith, and EU guidance treats it as a rights reservation (§E). Follow: treat it as binding, since being able to say "robots.txt followed" is the Q&A answer you want.
- **Drop sensitive fields vs keep them for audit.** Reis says to drop what you do not need (p.381-383). O'Neil says to keep protected attributes in a separate audit table to measure disparate impact (p.183). Follow: drop them by default; keep an audit-only column only when fairness is part of the pitch, preferably using public aggregates such as census slices rather than personal records.
- **Holdout with tiny data.** Leek's 70/30 split assumes enough rows (p.51). With under about 100 rows, use cross-validation on everything and say the interval is wide; O'Neil's warning against scoring individuals from small samples (p.14, p.123) is the stop rule.
