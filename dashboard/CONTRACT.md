# Agent Ops Dashboard: data contract (fixed; build against this)

A local, projector-friendly dashboard that shows every Claude agent working on Backfire across the team's laptops, which pipeline and step each is on, and an animated flow of messages between pipelines.

## Where the data comes from (all GitHub, repo `Proton-Designer/HackUTD26`)
1. **Messages** = GitHub Issues + their comments (the agent comms bus, see `../AGENT_COMMS_SETUP.md`).
   - Thread opener: an issue titled `[FROM→TO] subject`, labels `from:P#` and `to:P#|to:ALL` (targets P1 P2 P3 P4 P4a P4b ALL; `P4` means both P4a and P4b).
   - Replies: issue comments. Sender = the `_from: P# · HH:MM_` signature line in the body (regex `_from: (P1|P2|P3|P4a|P4b|P4) `). Recipients of a reply = the issue's `to:` labels plus the issue's original sender, minus the reply's sender.
   - A comment starting `Resolved:` is a close (kind `close`).
2. **Presence** = one issue labeled `presence` titled `📡 Agent presence board`. Each machine edits ONE comment of its own (never new comments). Comment body:
   ````
   <!-- presence:P1:ayman-mbp -->
   ```json
   {"v":1,"pipeline":"P1","host":"ayman-mbp","person":"Ayman Mohammed","os":"macOS",
    "status":"working","step_n":3,"step_text":"Telnyx number bought, wiring call.initiated",
    "last_tool":"Edit","last_file":"server/routing.py",
    "sessions":1,"agents":3,"updated":"2026-11-08T05:30:12Z"}
   ```
   ````
   - `status`: `working` | `idle` (agent stopped, waiting on its human) | `blocked` | (dashboard derives `offline` when `updated` is older than 10 min, `stale` when older than 3 min).
   - `sessions` = Claude Code sessions active on that machine in the last 10 min; `agents` = sessions + subagents active in the last 10 min.
   - `step_n` is 1-based into that pipeline's `steps` in `pipelines.json` (may be null); `step_text` free text (≤140 chars).
3. **Pipeline definitions** = `dashboard/pipelines.json` (ids, names, owners, colors, step titles).

## Server: `dashboard/server.py` (Python 3.9+ stdlib only; macOS + Windows + Linux)
- Run: `python3 dashboard/server.py` (Windows: `py dashboard\server.py`). Flags: `--port 7777` (default), `--repo owner/name`, `--interval 6` (poll seconds), `--demo` (no GitHub: synthetic but realistic data, new messages every few seconds, agents changing steps). If no token can be found it falls back to demo and says so in `mode`.
- Token: env `GITHUB_TOKEN` / `GH_TOKEN`, else output of `gh auth token`.
- Polls with conditional requests (`If-None-Match` ETags; 304s don't spend rate limit):
  - `GET /repos/{repo}/issues?state=all&per_page=100&sort=updated` (exclude PRs), then for message bodies use issue `body`;
  - `GET /repos/{repo}/issues/comments?since=…&per_page=100&sort=updated` (repo-wide comments, one call);
  - presence issue comments (find the issue by label `presence`).
- Keeps an in-memory, ordered message log (dedupe by id), and serves:
  - `GET /` → `public/index.html`; `GET /static/*` → `public/*`
  - `GET /api/state` → the JSON below
  - `GET /api/events` → Server-Sent Events: `event: state` (full state JSON, sent on connect and whenever anything changes) and `event: message` (one message object, for each NEW message, in order). Heartbeat comment line every 15 s.
- Binds `0.0.0.0` so a projector laptop on the same Wi-Fi can open `http://<ip>:7777`. Prints the local and LAN URLs on start.
- Never crashes on network errors: keeps last good state, sets `health.github` to `"error: …"`.

### `/api/state` JSON
```json
{
  "generated_at": "2026-11-08T05:31:00Z",
  "mode": "live",                      // "live" | "demo"
  "repo": "Proton-Designer/HackUTD26",
  "health": {"github": "ok", "rate_remaining": 4870, "last_poll": "2026-11-08T05:30:58Z"},
  "project": "Backfire · HackUTD 2026",
  "pipelines": [ {"id":"P1","name":"…","owner":"Ayman","color":"#00e5ff","steps":["…"],
                  "machines":["P1@ayman-mbp"], "status":"working", "step_n":3, "step_text":"…",
                  "agents":3, "msgs_out":4, "msgs_in":2} ],
  "machines": [ {"key":"P1@ayman-mbp","pipeline":"P1","host":"ayman-mbp","person":"Ayman Mohammed","os":"macOS",
                 "status":"working","step_n":3,"step_text":"…","last_tool":"Edit","last_file":"server/routing.py",
                 "sessions":1,"agents":3,"updated":"…","age_s":12} ],
  "messages": [ {"id":"c6717637422","thread":5,"kind":"reply","from":"P1","to":["P2","P3","P4a","P4b"],
                 "title":"Comms protocol is live","body":"first 400 chars, signature + 'Generated by' footer stripped",
                 "created_at":"…","url":"https://github.com/…"} ],     // newest last, max 200
  "threads": [ {"number":5,"title":"Comms protocol is live","state":"open","from":"P1","to":["ALL"],
                "replies":1,"updated_at":"…","url":"…"} ],
  "stats": {"messages_total":12,"messages_last_hour":7,"open_threads":4,"machines_online":3,"agents_total":7}
}
```
- `to` is always expanded to concrete pipeline ids (ALL → every other pipeline; P4 → P4a + P4b).
- `pipelines[].status/step_*` come from the most recently updated machine of that pipeline; `offline` if none fresh.

## Frontend: `dashboard/public/index.html` (+ optional `app.js`, `style.css`), no build step, no CDN required
Must work offline on the projector (inline or local files only; system font stack + monospace). Dark, techy, readable from the back of a room (big type, high contrast), 16:9 first, still sane on a laptop.
- **Header:** project name, LIVE/DEMO badge, clock (America/Chicago), hackathon countdown to 2026-11-08 09:00 local (submission), GitHub health dot, stats (agents online, machines, messages/hour, open threads).
- **Center: the network graph.** One node per pipeline (P1, P2, P3, P4a, P4b) on a ring, colored by `pipelines.json`. Each node shows id, name, owner, agent count, status ring (working = animated pulse, idle = dim, blocked = red, offline = grey dashed). Edges appear between pipelines that have exchanged messages (thickness ∝ count). **Every new message animates as a glowing packet travelling from sender to each recipient** (one packet per recipient), and briefly flashes the subject near the edge. On first load, replay the last ~10 messages quickly so the screen is never empty.
- **Pipeline lanes:** one card per pipeline: its steps as a horizontal progress track (done = filled, current = glowing, future = outline), current `step_text`, machines (host, person, OS icon, agents/sessions, last tool + file, "updated 12s ago"), stale/offline styling.
- **Message feed:** live scrolling list (newest on top): time, `FROM → TO` chips in pipeline colors, kind (thread/reply/close), subject, first line of body. New items slide in.
- Data: connect to `/api/events` (SSE); on error fall back to polling `/api/state` every 3 s. Diff messages by `id` so each animates once.
- Keyboard: `F` fullscreen, `R` replay recent messages, `D` toggle details.
